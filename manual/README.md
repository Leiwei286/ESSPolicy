## 结构化 JSON 的最小写法

字段与 `data/policies.json` 完全一致，只有 6 个必填，其余留空会自动补默认值：

```json
[
  {
    "title": "关于明确储能价格政策有关事项的通知",
    "region": "吉林",
    "level": "省级",
    "issuer": "吉林省发展和改革委员会",
    "publish_date": "2026-06-08",
    "category": "容量电价政策",
    "doc_no": "吉发改价格联〔2026〕240号",
    "effective_date": "2026-07-01",
    "summary": "明确独立储能容量补偿按 330 元/kW·年执行，执行期三年",
    "key_points": ["容量补偿 330 元/kW·年", "考核周期按自然年，年底清算", "储能不参与煤电容量电价分摊"],
    "metrics": { "cap_price": 330, "duration_h": 4, "note": "按额定功率计，8h 封顶折算" },
    "impact": "利多",
    "logic": "容量补偿抬升固定收益，降低对峰谷价差的依赖",
    "model_flag": "容量电价",
    "star": 3,
    "source_url": "https://fgw.jl.gov.cn/...",
    "note": "手动收集，原文为官网 PDF"
  }
]
```

`metrics` 固定 8 键（无值留空，**不要填 0**）：`cap_price` / `pv_spread` / `storage_ratio` / `duration_h` / `dispatch` / `scale_gw` / `scale_gwh` / `ancillary`，另有 `note` 写口径。

## 入库命令

```bash
python tools/ingest_manual.py            # 只出报告，不动数据（默认）
python tools/ingest_manual.py --apply     # 确认后落盘：合并 + 更新 meta + 追加 changelog + 重新打包
```

报告分五段：格式校验 → 重复判定 → 真正新增 → 口径冲突 → 指标补全。**看到「口径冲突」不要直接落盘**，先判定哪个是现行有效值，这类问题（青海 165/185、四川 350/400）是之前最容易踩的坑。

## 去重规则

按以下顺序命中即判重复，只把新链接、新要点、空缺指标并入旧条目，**不新增一条、不覆盖已有数值**：

1. `bjx_url` 相同
2. `source_url` 相同
3. 标题归一化后一致（去掉书名号、标点、「关于…的通知」外壳）
4. 同省份 + 同发文字号

未命中硬去重、但同省同分类且标题相似度 ≥ 0.75 的，不进库但会提示「疑似同一政策的不同版本」，供人工判断。

## 与主源的关系

- 主源仍是北极星储能网政策频道，手动源用于补漏：官网原文、公众号深度解读、券商汇总、以及北极星未收录的省份文件。
- 手动源条目的 `channel` 字段为 `ima`，主源条目为 `bjx`，可在 `data/policies.json` 里区分，但**看板不新增筛选器**（按你的要求不改面板）。
- 同一政策主源与手动源都有时，以条目内容更完整的一方为准，链接互相补充，不产生第二条。
