## 一、这套东西是怎么搭的

```
储能政策跟踪/
├── index.html                 看板本体（双击打开，无需服务器）
├── data/
│   ├── policies.json          ★ 政策主数据，唯一需要每周修改的文件
│   ├── meta.json              覆盖区间、更新说明、分类与重点省清单
│   ├── changelog.json         变更日志，追加写入
│   ├── source_watchlist.json  固定信息源清单（14 个，含 9 重点省官方栏目）
│   └── data-bundle.js         由 build_data.py 自动生成，勿手改
├── tools/
│   └── build_data.py          JSON → JS 打包 + 字段校验
└── docs/
    └── 看板设计说明.md         本文件
```

**为什么多一层 data-bundle.js**：浏览器在 `file://` 协议下会拦截 `fetch` 读取本地 JSON（CORS 限制），但允许 `<script src>` 加载同目录 JS。所以把 JSON 包一层赋值语句，看板就能双击直接打开。这是为了「不用起本地服务器」付出的唯一代价。

## 二、每周更新 SOP（约 20 分钟）

1. 抓 `https://chuneng.bjx.com.cn/zc/1` 与 `/zc/2`，提取条目，与 `policies.json` 里已有 `bjx_url` 集合比对 → 候选新增。
2. 按入库判定规则筛掉非政策条目。
3. 逐条打开原文，补 `issuer`、`doc_no`、`effective_date`、`source_url`。
4. 写 `summary`、`key_points`（3-5 条）、`metrics`，判 `impact` / `star` / `model_flag`。
5. 生成变更清单交用户确认（新增候选 / 状态变更 / 疑似失效）。
6. 确认后写入 `policies.json` → 运行打包 → 刷新看板 → 追加 `changelog.json`。
7. **读一遍 ima「储能政策手动收集」文件夹 + 检索公众号「储能与电力市场」本周文章**，与本周抓取结果合并去重后再交确认（详见第九、十节）。

```bash
python tools/build_data.py
```

脚本会自动做三件事：校验必填字段与 id 唯一性、按实际数据重算 `meta.counts`、重新生成 `data-bundle.js`。

### 链接规则（2026-11-12 起生效）

- `source_url` **只在能直接确认官方发文页时才填**，不为找官方链接反复抓取——每条浪费 3-5 次请求而成功率不高。
- 找不到官方页时 `source_url` 留 `null`，`bjx_url` 作为唯一必需链接，看板点击直达北极星报道。
- 允许把「北极星转载的文件全文页」（形如 `news.bjx.com.cn/html/日期/编号.shtml`）填入 `source_url`，此时须在 `note` 注明「为转载全文页，非政府官网原文」。

### 入库判定规则

| 处理 | 类型 |
|---|---|
| ✅ 收 | 办法、细则、方案、规划、通知、清单、征求意见稿、批复 |
| ✅ 收 | 项目清单 / 优选结果 / 建设计划（直接对应装机需求） |
| ⚠️ 收但降星 | 地方补贴申报通知（只对个别项目有效） |
| ❌ 不收 | 企业/园区申报公示、环评用地公示、行业标准（除非涉并网门槛）、人事会议报道、锂钴矿端、新能源汽车与充电桩（除非含配储条款） |

### 失效识别四条规则

1. 新文件正文出现「废止 / 停止执行 + 旧文件名」→ 旧条目 `已废止`
2. 同名新版发布（含「修订 / 2026 年版」）→ 旧条目 `被替代`，填 `superseded_by`
3. 政策自带有效期且已过期 → `已失效`
4. 省级文件被国家层面同类文件覆盖 → `被替代`，注明「上位文件替代」

### 去重主键

`bjx_url`；缺失时用 `title + issuer + publish_date` 归一化哈希。同一文件被多篇报道时合并为一条，其余链接记入 `note`。

## 三、字段字典

### A 身份与归属
| 字段 | 说明 |
|---|---|
| `id` | `省代码-发文日期-序号`，如 `NM-20261111-01` |
| `title` | 文件全称，剥掉「重磅 / 速看」等媒体前缀 |
| `region` | 全国 / 省级行政区名 |
| `level` | 国家 / 省级 / 市级（按发文单位层级，不看发布平台） |
| `issuer` | 发文单位，多部门用顿号分隔 |
| `doc_no` | 发文字号，无则 `—` |
| `doc_type` | 正式文件 / 征求意见稿 / 规划 / 清单 / 批复 / 方案 / 通知 / 指导意见 / 实施细则 |

### B 时间与状态
| 字段 | 说明 |
|---|---|
| `publish_date` | 取文件落款日期；落款缺失才用发布日 |
| `effective_date` | 执行起始日；查不到填 `待核实`，**不臆造** |
| `status` | 现行有效 / 征求意见 / 已废止 / 被替代 / 已失效 / **历史索引** |
| `superseded_by` | 替代文件 id 或标题 |
| `star` | 1-3 星（索引层上限为 2） |
| `model_flag` | 无 / 容量电价 / 价差 / 调用与结算 / 配储比例 / 装机规模 |

**`历史索引` 状态的含义**：仅用于 `tier=index` 的早期条目（2022-01 至 2025-01）。这类条目没有回溯原文，无法判定是否仍有效，因此不归入「现行有效」，而是单独成类、在看板中**默认隐藏**。看板列表顶部会提示隐藏条数并提供「展开查看」。任何时候都不应把索引层条目当作现行政策引用——它的用途只有两个：追溯某项规则的来源，以及在比对「新旧文件」时提供时间锚点。

**星级口径**
- ★★★ 直接改变项目 IRR 或装机节奏预测，需立即更新测算表
- ★★ 改变某省规则环境但幅度有限，或只影响单一技术路线
- ★ 方向性表述、规划愿景、无量化条款

### C 分类
`category` 主分类单选（10 类），`sub_tags` 为辅助标签。

### D 经济性提炼
| 字段 | 说明 |
|---|---|
| `summary` | 一句话结论，≤50 字，只讲「改了什么」 |
| `key_points` | 3-5 条，每条 ≤60 字，只写机制与数字，不写评价 |
| `metrics` | 固定键，无则留空不填 0 |
| `impact` | 利多 / 利空 / 中性 |
| `logic` | 一句话因果链 |

`metrics` 固定键与单位：

| 键 | 含义 | 单位 |
|---|---|---|
| `cap_price` | 容量补偿 / 容量电价 | 元/kW·年 |
| `pv_spread` | 峰谷价差或现货价差 | 元/kWh |
| `storage_ratio` | 配储比例 | % |
| `duration_h` | 时长要求 | h |
| `dispatch` | 保底调用 / 结算次数 | 次/日 或 h/年 |
| `scale_gw` / `scale_gwh` | 装机或清单规模 | GW / GWh |
| `ancillary` | 辅助服务补偿 | 元/MW 或 元/kWh |
| `note` | 口径备注（区间、含税与否、折算方式） | — |

### E 来源与元数据
`source_url`（官方原文，优先）、`source_name`、`bjx_url`、`tier`（`full` / `index`）、`first_seen`、`last_checked`、`note`。

| 分类 | 收什么 | 关键指标 |
|---|---|---|
| 储能装机目标 | 规划/行动方案里的装机规模与时点 | `scale_gw` / `scale_gwh` |

| 峰谷电价政策 | 分时时段划分与浮动比例 | `pv_spread` |
| 系统运行费规则 | 系统运行费/辅助服务费分摊、输配电价 | — |

## 五、看板交互

- **三视图**：列表（默认）/ 矩阵（省 × 分类密度）/ 时间轴（按月分段看节奏）
- **默认状态筛选**：只显示「现行有效 + 征求意见」，已废止/被替代需手动勾选——防止拿旧政策做判断
- **历史索引默认隐藏**：846 条 2022-2025 的索引条目单独归入「历史索引」状态，默认不显示；列表顶部会提示隐藏条数并提供「展开查看」一键打开。索引卡片无要点区、整体降透明度，视觉上与全字段条目区分
- **矩阵空白格是信号**：某省某类别长期无政策，说明该机制尚未建立，项目收益假设缺乏依据
- **排序**：发文日期 / 生效日期 / 星级 / 地区
- **搜索**：政策名 + 发文单位 + 要点 + 摘要 + 指标备注

**顶部指标带的读法**：「全字段 N 条 / 共 M」区分了精编条目与索引条目的规模；「需改测算假设」只统计全字段条目，索引层不计入，避免虚高。

## 六、当前已知缺口（下批补齐）

1. **`pv_spread` 按用户决定长期留空**。2026-11-12 起不再折算绝对价差，峰谷类政策只在 `key_points` 里保留官方浮动比例（如山东「峰+70%/谷-70%/尖峰+100%/深谷-90%」、河南「1.72:1:0.45」），不做二次计算。看板横向比省请改看「峰谷电价政策」分类下的要点文本。
2. **甘肃已补齐**（5 条：330 元/kW·年可靠容量补偿、调频 15 元/MW、不再强制配储、防倒卖、2025 重大项目清单超 8.6GWh）。**仍缺**：甘肃省级独立储能专项清单未检索到，需确认是否仅以市级/重大项目形式披露。
3. **`storage_ratio` 现 7 条有值**（山西 15%/4h、广东绿电直连 60%、宁夏 20%/4h、上海陆上风电 20%/4h、上海方案 20%/4h、海南就近消纳 60%、全国就近消纳 60%）。多数省份配储要求以「鼓励」表述或写在项目申报文件里，未形成单一数值。136 号文配储脱钩后，这一字段的可比性会持续下降。
4. **2025 年 1-9 月全国层级 6 条已补齐**（2025-11-12 补录）：新型储能规模化建设专项行动方案（2027 年 1.8 亿千瓦/2500 亿元）、输配电定价成本监审（储能不得计入，status 标「被替代」指向 11-27 正式稿）、就近消纳 730 小时、八部门制造业行动方案、电力业务许可豁免、新型电力系统首批试点。
5. **北京、西藏仍为 0 条**。北京的政策多为充电设施、固态电池示范，与储能项目经济性关联弱；西藏在北极星政策频道基本无省级储能文件。两者是否继续跟踪需确认。
6. **第 3b 批已做完 17 条，剩 87 条低分候选未入库**。候选生成改为按标题量化线索打分（`tools/screen_batch3b.py`）：104 条候选里 qty≥2 的 42 条经人工复核后入 17 条，其余 87 条 qty≤1（标题无任何数字），判断为量化信息不足、边际价值低。若后续需要，候选清单在 `data/_batch3b_candidates.json`。
7. **原始发文页按新规则不再逐条追溯**。`source_url` 能确认官方链接才填，否则留空、以 `bjx_url` 为准。
8. **`source_watchlist.json` 中 13 个官方栏目 URL 仍为 `verified: false`**，首次周更时逐一点开确认。
9. **索引层已建，但只到 2022-01**（2025-11-12 第 4 批）。北极星政策频道实测可回溯至 **2014-06-23**，共 115 页 7357 条，是目前全部数据的来源上限。索引层覆盖 2022-01-01 至 2025-01-09 共 846 条；**2014-2021 年约 1900 条政策类条目未建索引**，判断依据是这一时期的容量电价、现货规则、配储要求基本已被 2022 年后文件替代，保留价值低于维护成本。如需回补，原始条目已全部存在 `data/_all_items.json`（7357 条），无需重新抓取。
10. **索引层 846 条存在已知误判**：地区靠标题关键词判定，部分地市/县级文件可能被归为省级（如标题不含「市/州/县」字样的开发区、县级市文件）；发文单位只能从标题提取，775 条填「待核实」。索引层定位为「制度沿革检索」，不用于直接引用，因此未逐条回溯修正。

### 已判定口径：青海容量电价 165 vs 185（2026-11-12 结案）

**结论：不是并列口径，165 元是首版征求意见稿的历史参数，已被正式稿 185 元取代。现行唯一有效值取 185 元/(kW·年)。**

判定链条如下，三项参数在同一时期被同步改写：

| 时间 | 文件 | 标准 | 高峰持续时长 | 容量供需系数 |
|---|---|---|---|---|
| 2026-02-25 | 《关于建立青海省发电侧容量电价机制的通知(征求意见稿)》 | 165 元/kW·年 | 4h（近 3 年前 0.2% 时段） | 1.04（2023-2025：需求 22102.96MW / 可靠容量 21167.93MW） |
| 2026-04-21 | 《青海省发电侧可靠容量补偿机制(征求意见稿)》二次征求意见 | 185 元/kW·年 | 8h（近 3 年前 3% 时段） | 0.92（2020-2025：需求 20920MW / 可靠容量 22788MW） |
| 2026-07-07 | 《青海省发电侧可靠容量补偿机制》正式印发（青发改价格规〔2026〕365号） | 185 元/kW·年 | 8h | 0.92 |
| 2026-07-29 | 《关于公布青海省发电侧容量补偿机制项目清单的通知》（青发改价格〔2026〕406号） | 月度 15.4 元/kW | 8h | 0.92 |

名称本身也变了：2 月叫「容量电价机制」、按「有效容量」补偿；4 月起改叫「可靠容量补偿机制」、按「可靠容量」补偿，并把统计窗口从 2023-2025 三年扩到 2020-2025 六年。所以这不是调价，是机制重写。

**对测算影响最大的不是 165 还是 185，而是折算强度和起算月份：**

1. **折算强度**：可靠容量系数 =（1 − 10.39%）× Min(满功率放电时长 ÷ 8, 100%)。按额定功率计的实际补偿强度：2h 项目约 **38 元/kW·年**（名义值的 20.6%）、4h 约 **83 元**（41%）、8h 及以上约 **152 元**（82.4%）。原 `QH-20260707-01` 的 note 写「实际到账约为名义值的 82%」只适用于 8h 及以上项目，已改写。首批清单里格尔木宏储源 100MW/2h 核定可靠容量 22.4MW、年容量电费 381 万元，可作校核样本。

### 宁夏：20GW 为准，10GW 是误记（2026-11-13 判定）

原先是全库唯一未决的目标口径冲突。现已判定：**宁夏取 20GW**，来源《美丽宁夏建设「十五五」规划》（宁政发〔2026〕25号，2026-08-27，第 18 条）。

**另一条官方口径（可补 GWh 与时长）**：宁夏广电报道「到2030年，宁夏新型储能将达到2000万千瓦/4小时，年综合利用1200小时以上」。据此 `duration_h=4`、`scale_gwh=80`（20GW×4h，属于**折算值**，已在 metrics.note 标明），`dispatch` 未填（全库该字段语义不统一，混填会误导）。

| 步骤 | 合计 |
|---|---|
| 汇总表 24 省加总（含宁夏 10） | 280GW |
| 宁夏修正为 20GW | ≈290GW |
| 加青海 2030 年 10GW（2026-11-13 入库） | ≈**300GW** |

正好等于国家《新型能源体系建设「十五五」规划》提出的 2030 年新型储能 **300GW** 目标。反过来说，如果宁夏真是 10GW，25 省加总只有约 290GW，与国家级目标的缺口就对不上了——这是 10GW 偏低的旁证。

**取数提醒**：宁夏 20GW 分摊五年约年均 4GW，而 2026 年已在清单内的各市电网侧储能合计约 8.3GW（中卫 3.38、宁东 1.0、石嘴山 1.4、银川 1.5+1.0），前两年节奏会明显高于年均值。真正的约束不在目标，而在外送通道（银东、灵绍、中衡三条直流合计 2000 万千瓦）与本地消纳，以及 165 元/kW·年容量电价下的项目收益。

### 一个必须记住的坑：本机 git 连不上 github.com

本机网络环境 **github.com 不可达**（直连超时、系统代理 `127.0.0.1:55073` 对 github.com 返回 502），但 **api.github.com 与 leiwei286.github.io 直连正常**。

解决办法：给仓库配置本机 Clash 代理（`127.0.0.1:7897`），已写入 `.git/config`：

```bash
git config --local http.proxy http://127.0.0.1:7897
git config --local https.proxy http://127.0.0.1:7897
```

`schannel` 与 `openssl` 两种 TLS 后端都试过，报错都是 `unexpected eof` / `CONNECT tunnel failed`，**根因是网络阻断而非证书问题**，不要浪费时间调 TLS 参数。Clash 未启动时 push 会失败，先确认 7897 端口在监听。

### 周更后的发布流程

```bash
python tools/build_data.py      # 必须：重新生成 data-bundle.js，否则线上还是旧数据
python tools/refresh_meta.py
python tools/qa_check.py        # 确认无阻断性问题
git add -A && git commit -m "数据更新：<本周要点>"
git push
```

**最容易漏的一步是 `build_data.py`**：`index.html` 在浏览器里读的是 `data-bundle.js`，只改 `policies.json` 不重新打包，本地和线上都不会变。
